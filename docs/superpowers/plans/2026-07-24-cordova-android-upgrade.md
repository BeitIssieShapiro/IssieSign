# Cordova Android Upgrade to v15 / API 36 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade cordova-android from 13.0.0 to 15.1.0 and raise targetSdkVersion to API 36 to meet Google Play's August 31 2026 deadline.

**Architecture:** Rename the existing `android-app` to `android-app-old` as a safety backup, then create a fresh `android-app` Cordova project from scratch with cordova-android 15.1.0. All project-specific customizations (gradle, manifest, Java patches, asset packs) are re-applied to the new project. iOS is out of scope — android only.

**Tech Stack:** Cordova CLI (global), cordova-android 15.1.0, Gradle 8.13, AGP 8.7+, API 36 (Android 16), Node >=20.17

## Global Constraints

- No git operations at any step
- Work entirely inside `android-app/` directory unless noted
- `cordova-android`: exactly `^15.1.0`
- `targetSdkVersion` / `compileSdkVersion`: **36**
- `minSdkVersion`: keep at **24**
- `gradle.properties` must keep: `org.gradle.java.home=/Users/i022021/Library/Java/JavaVirtualMachines/jbr-17.0.12/Contents/Home`, `android.useAndroidX=true`, `android.enableJetifier=false`, `org.gradle.jvmargs=-Xmx4048m`
- Asset packs `:issiesign_assets` and `:issiesign_assets3` must be re-included in `settings.gradle`
- `cordova plugin add` commands must be run from inside `android-app/`
- iOS is out of scope — android only

### Task 8: Re-apply Java source customizations

**Files:**
- Modify: `android-app/platforms/android/app/src/main/java/com/issieshapiro/signlang/MainActivity.java`
- Modify: `android-app/platforms/android/app/src/main/java/org/apache/cordova/file/ContentFilesystem.java`

- [ ] **Step 1: Add getSupportActionBar().hide() to MainActivity**

Open `MainActivity.java`. In `onCreate`, add `getSupportActionBar().hide();` before `loadUrl(launchUrl);`:

```java
@Override
public void onCreate(Bundle savedInstanceState)
{
    super.onCreate(savedInstanceState);

    Bundle extras = getIntent().getExtras();
    if (extras != null && extras.getBoolean("cdvStartInBackground", false)) {
        moveTaskToBack(true);
    }

    getSupportActionBar().hide();
    loadUrl(launchUrl);
}
```

- [ ] **Step 2: Apply ContentFilesystem.java toNativeUri patch**

Find `ContentFilesystem.java` at:
`platforms/android/app/src/main/java/org/apache/cordova/file/ContentFilesystem.java`

In the `toNativeUri` method, replace the line that computes `authorityAndPath` with:
```java
String authorityAndPath = inputURL.uri.getEncodedPath().substring(12 + this.name.length() + 2);
```

The full method start should look like:
```java
public Uri toNativeUri(LocalFilesystemURL inputURL) {
    String encodedPath = inputURL.uri.getEncodedPath();
    String authorityAndPath = inputURL.uri.getEncodedPath().substring(12 + this.name.length() + 2);
    if (authorityAndPath.length() < 2) {
        return null;
    }
```

Note: The original generated code computes `authorityAndPath` differently. This is a required patch per [cordova-plugin-file issue #525](https://github.com/apache/cordova-plugin-file/issues/525).
